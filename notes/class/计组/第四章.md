## 1. 本章主线与性能指标

对应课件 p.2–6、p.148。

本章研究：**如何用数据通路和控制器实现指令，以及如何让多条指令重叠执行来提高处理速度。**

```text
ISA：规定指令语义与编码
 ↓
数据通路：提供运算、存储、传送能力
 ↓
控制器：决定选择哪条路径、做什么运算、写到哪里
 ↓
单周期 → 五级流水线 → 转发/停顿/预测 → 多发射/乱序执行
```

CPU 执行时间：

$$
T_{CPU}=IC\times CPI\times T_{clk}=\frac{IC\times CPI}{f_{clk}}
$$

| 因素 | 含义 | 主要影响因素 |
| --- | --- | --- |
| IC | 动态执行的指令数 | 算法、ISA、编译器 |
| CPI | 平均每条指令所需周期数 | 流水线、冒险、存储系统、指令组合 |
| 时钟周期 | 一个周期的时间 | 最慢路径、级数划分、硬件延迟 |

**不能只比较频率或 CPI。**单周期 CPI=1，但周期很长；流水线可能因停顿而 CPI>1，仍因周期短而更快。

最初讨论的 RISC-V 简化子集：访存 `lw/sw`，算术逻辑 `add/sub/and/or`，控制转移 `beq`。后面又出现 `ld/sd/addi/blt` 等指令。最初的数据通路不是完整 RISC-V 实现。

## 2. 逻辑设计与时钟约定

对应课件 p.7–11。

### 2.1 组合逻辑与状态元件

| 类型                       | 特点                | 例子               |
| ------------------------ | ----------------- | ---------------- |
| 组合逻辑 combinational       | 输出由当前输入决定，不保存历史状态 | ALU、加法器、MUX、译码逻辑 |
| 状态/时序元件 state/sequential | 保存信息，按时钟和使能更新     | PC、寄存器、流水线寄存器    |

多位数值通过总线传递，一根线承载一位。寄存器堆内部既有存储状态，也有读写逻辑。

MUX（多路选择器）按选择信号选出一路输入：`S=0→I0`，`S=1→I1`。不能把多个输出线直接连起来替代 MUX，否则不同输出可能冲突。

### 2.2 上升沿触发与写使能

课件采用上升沿触发：时钟从 0 变 1 时更新。带写使能的寄存器：

```text
时钟有效沿且 Write=1：Q ← D
Write=0：Q 保持
```

一个周期内，源状态元件输出旧值，组合逻辑传播计算，到下个有效沿由目标状态元件保存结果。**数据在周期内部传播，状态在指定边沿更新。**

### 2.3 最长路径决定周期

教学模型常只比较组合延迟。补充更完整的理解：

$$
T_{clk}\ge t_{clk\to Q}+t_{comb,max}+t_{setup}+t_{skew}
$$

即源寄存器输出延迟、最长组合路径、建立时间和时钟偏差裕量之和。保持时间是另一项时序约束，不能仅靠延长周期解决。

## 3. 构建单周期数据通路

对应课件 p.12–20、p.28–34。

### 3.1 指令执行的共同步骤

1. PC 给出地址，从指令存储器取指。
2. 按 rs1/rs2 编号读取寄存器。
3. ALU 运算、计算有效地址或比较分支条件。
4. load/store 访问数据存储器。
5. 需要时写回寄存器，并更新 PC。

单周期把一条指令需要的上述操作放进**一个时钟周期**。不同指令使用不同的路径。

### 3.2 部件分工

| 部件 | 用途 |
| --- | --- |
| PC | 保存当前指令地址 |
| Instruction memory | 按 PC 取指 |
| Register file | 两个源读端口，一个目的写端口 |
| ImmGen | 按指令格式拼接立即数，符号扩展 |
| ALU | 算术逻辑运算、算访存地址、分支比较 |
| Data memory | 按有效地址读写数据 |
| PC+4 加法器 | 产生顺序地址 |
| 分支加法器 | 产生 PC 相对目标地址 |
| MUX | 选择操作数、写回值和下一 PC |
| Main control、ALU control | 产生控制信号 |

![单周期完整数据通路，PDF p.20](p020.png)

### 3.3 取指与位宽

课件以 64 位 PC/数据通路为背景，但基础指令长 **32 位=4 字节**：

$$PC_{next}=PC+4$$

**寄存器宽度不等于指令宽度。**这里暂不考虑压缩指令。

### 3.4 R 型指令

例：`add x5,x1,x2`。

```text
取指 → 读 R[x1]、R[x2] → ALU 相加 → 写入 R[x5]
PC ← PC+4
```

`sub/and/or` 路径相同，具体 ALU 运算不同；无需读写数据存储器。

### 3.5 Load

例：`lw x5,12(x1)`。

$$EA=R[x1]+\operatorname{SignExt}(12)$$

```text
取指 → 读基址 x1 → ALU 加立即数算地址 → 内存读取 → 写回 x5
```

ALU 输入 B 来自立即数，写回值来自内存。RV64 中 `lw` 读 32 位并符号扩展到 64 位，`ld` 读 64 位；课件简图省略部分宽度转换细节。

### 3.6 Store

例：`sw x5,12(x1)`。

```text
rs1=x1：基址
rs2=x5：待存数据
ALU：R[x1]+SignExt(12)
Data memory[有效地址] ← R[x5] 的低 32 位
```

**ALU 第二输入选立即数，但内存写数据仍来自 rs2。**store 不写通用寄存器；`sd` 存储 64 位。

### 3.7 BEQ

`beq x1,x2,offset` 同时需要：

1. ALU 做 `R[x1]-R[x2]`，结果为 0 则 `Zero=1`。
2. 分支加法器用**当前分支指令 PC**加有符号偏移。

$$PCSrc=Branch\land Zero$$

$$
PC_{next}=\begin{cases}
PC+\Delta_{bytes},&Branch\land Zero=1\\
PC+4,&\text{其他情况}
\end{cases}
$$

课件采用“半字位移左移 1 位”，即 $\Delta_{bytes}=\operatorname{SignExt}(imm)\ll1$。固定左移只是接线，不必使用通用移位器。

**注意立即数定义：**如果 ImmGen 已生成含最低位 0 的完整 B 型字节偏移，就直接加 PC，不能重复乘 2。课件 p.90 的 `beq …,16` 按“半字位移 16”算 `40+16×2=72`；不要把它无条件当作真实汇编器对数字操作数的规则。标签由汇编器计算相对地址。

### 3.8 字段、立即数与共享

补充常用指令字段位置：

| 字段 | 指令位 |
| --- | --- |
| opcode | `[6:0]` |
| rd | `[11:7]` |
| funct3 | `[14:12]` |
| rs1 | `[19:15]` |
| rs2 | `[24:20]` |
| funct7（R 型） | `[31:25]` |

- I 型 load：立即数 `[31:20]`。
- S 型 store：立即数由 `[31:25]` 与 `[11:7]` 拼接。
- B 型 branch：需要重排偏移位次，最低位固定为 0。
- 符号扩展：把符号位复制到高位，保持负数意义。

不同指令可以共享 ALU，但同一条指令不能在一个周期内让同一部件先后完成多个独立用途。取指与 load/store 访存会同时需要内存，因此这里分离指令和数据存储器；PC+4、分支目标、主 ALU 运算也可能并行，所以使用多个加法部件。

## 4. 单周期控制器与 ALU 控制

对应课件 p.21–35。

### 4.1 主控制信号

主控制器按 opcode 识别指令大类。

| 信号 | 0 | 1 |
| --- | --- | --- |
| ALUSrc | ALU 第二输入取 rs2 | 取扩展立即数 |
| MemtoReg（也写 MemReg） | 写回 ALU 结果 | 写回内存值 |
| RegWrite | 不写寄存器堆 | 写寄存器堆 |
| MemRead | 不读数据存储器 | 读数据存储器 |
| MemWrite | 不写数据存储器 | 写数据存储器 |
| Branch | 不是该模型的条件分支 | 是分支，还需看 Zero |

ALUOp 是另一个 **2 位分类信号**。

![带控制的单周期数据通路，PDF p.26](p026.png)

### 4.2 主控制表

| 指令 | opcode | ALUSrc | MemtoReg | RegWrite | MemRead | MemWrite | Branch | ALUOp |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| R 型 | 0110011 | 0 | 0 | 1 | 0 | 0 | 0 | 10 |
| lw | 0000011 | 1 | 1 | 1 | 1 | 0 | 0 | 00 |
| sw | 0100011 | 1 | X | 0 | 0 | 1 | 0 | 00 |
| beq | 1100011 | 0 | X | 0 | 0 | 0 | 1 | 01 |

X 是 don't care：对本条指令的最终状态没有影响。例如 sw 不写寄存器，写回 MUX 选哪路都不影响结果。**X 不代表 MUX 停止工作，也不代表其他控制可随意取值。**RegWrite、MemWrite 等副作用控制必须正确。

![课件最终控制表，PDF p.35](p035.png)

### 4.3 ALUOp 与最终 ALU control

```text
opcode → Main Control → 2 位 ALUOp
                            ↓
funct3、funct7 → ALU Control → 4 位 ALU operation → ALU
```

- `00`：load/store，做加法算地址。
- `01`：beq，做减法比较。
- `10`：R 型，再检查功能字段。

| ALUOp | funct7 | funct3 | 操作 | 最终 ALU control |
| --- | --- | --- | --- | --- |
| 00 | XXXXXXX | XXX | add | 0010 |
| 01 | XXXXXXX | XXX | sub | 0110 |
| 10 | 0000000 | 000 | add | 0010 |
| 10 | 0100000 | 000 | sub | 0110 |
| 10 | 0000000 | 111 | and | 0000 |
| 10 | 0000000 | 110 | or | 0001 |

**为什么不直接由主控制器产生四位信号？**可以直接译码，但分层后主控制器只分类，ALU 控制器再选具体运算，逻辑更模块化，多类指令也能复用加法。2 位/4 位和这些编码是此硬件设计的选择，不是 ISA 强制。

### 4.4 从真值表构建逻辑

p.24–25 使用 `Instr[30]`、`Instr[14:12]`、`ALUOp[1:0]` 共 6 个输入，为 4 个输出分别建立布尔函数。

在本子集中 add/sub 的 funct7 只有 bit 5 不同，即指令 bit 30，可据此简化。完整 ISA 不能一律只看这个位。做题先按语义列真值表，再化简电路。

## 5. 单周期性能与局限

对应课件 p.36–38。

### 5.1 关键路径

假设存储器 200 ps、ALU/加法器 200 ps、寄存器堆读或写各 100 ps，其他延迟忽略：

| 指令 | 取指 | 读寄存器 | ALU | 数据访存 | 写回 | 总延迟 |
| --- | --- | --- | --- | --- | --- | --- |
| R 型 | 200 | 100 | 200 | — | 100 | 600 ps |
| load | 200 | 100 | 200 | 200 | 100 | **800 ps** |
| store | 200 | 100 | 200 | 200 | — | 700 ps |
| beq | 200 | 100 | 200 | — | — | 500 ps |

**时钟周期至少 800 ps，所有指令都使用这个周期。**R 型不能因为自身只需 600 ps 就提前启动下一条。

![关键路径及延迟假设，PDF p.36](p036.png)

load 关键路径：`取指存储器→寄存器堆读→ALU→数据存储器读→寄存器写回`。

课件还列 jal 为 200 ps，但前面未给 jal 的完整实现。若扩展 jal，需同时加入目标 PC 与 `rd←PC+4` 返回地址路径和控制，重新求最长延迟，不能无条件照搬该数字。

### 5.2 优缺点

优点：结构直观，控制简单，易于理解验证。

缺点：最慢指令决定周期，快指令浪费时间；复杂运算会进一步拖长周期；同周期资源不能分时复用，可能需复制部件；没有利用指令间重叠。

下一步通过流水线提高**吞吐率**，不保证单条指令延迟缩短。

## 6. 五级流水线与性能计算

### 6.1 五个阶段

| 阶段 | 英文 | 工作 |
| --- | --- | --- |
| IF | Instruction Fetch | 取指、产生顺序地址 |
| ID | Instruction Decode / Register Read | 译码、读寄存器、生成立即数和控制 |
| EX | Execute | ALU 运算或算有效地址 |
| MEM | Memory Access | 数据访存 |
| WB | Write Back | 写回寄存器 |

```text
       C1  C2  C3  C4  C5  C6  C7  C8
I1     IF  ID  EX  MEM WB
I2         IF  ID  EX  MEM WB
I3             IF  ID  EX  MEM WB
I4                 IF  ID  EX  MEM WB
```

store 没有实际写回，也可在统一五级图中经过一个无写入动作的 WB 槽位。

### 6.2 吞吐率不等于单条延迟

- 延迟：一条指令进入到完成的时间。
- 吞吐率：单位时间完成的指令数。
- 理想单发射流水线充满后每周期完成一条，但每条仍经历多级。

课件五级为 200、100、200、200、100 ps，忽略级间开销，周期为 200 ps；一条指令延迟约 `5×200=1000 ps`。单周期指令延迟为 800 ps，但完成间隔也是 800 ps，吞吐较低。

![单周期与流水线时间对比，PDF p.42](p042.png)

注意图中一个巧妙的设计，我们在读Reg时，在后半周期读，在写Reg时，前半周期写（仅此是在下降沿写），这样可以节省出一个周期。

### 6.3 周期数与加速比

n 条指令、k 级、无冒险单发射：

$$C_{pipe}=n+k-1$$
$$T_{pipe}=(n+k-1)T_{clk,pipe}$$
$$Speedup=\frac{nT_{clk,single}}{(n+k-1)T_{clk,pipe}}$$

n 很大且各级均衡时，加速比可接近 k；不均衡时受最慢级限制。

**本课件长程序极限为 800/200=4 倍，不是 5 倍。**4 条指令单周期用 3200 ps，流水线用 `(4+4)×200=1600 ps`，仅快 2 倍。

更实际的周期：

$$T_{clk,pipe}\ge\max_i(t_i)+t_{pipeline\ overhead}$$

级数越多，寄存器开销、分支损失和控制复杂度越难忽略。

### 6.4 含停顿的性能

若额外停顿/冲刷共 S 周期：

$$C=n+k-1+S,\qquad CPI_{finite}=\frac{n+k-1+S}{n}$$

长程序近似：

$$CPI\approx1+\text{平均每条指令的额外停顿}$$
$$\Delta CPI_{branch}=f_{branch}\times r_{mispredict}\times P_{mispredict}$$

前者包括访存、数据和控制损失。相加时要检查不同损失是否重叠，不能对同一周期重复收费。

### 6.5 ISA 与流水线

基础 32 位定长指令、规则字段位置，便于同级译码和读寄存器；load/store 将访存集中到特定指令，便于 EX 算地址、MEM 访存。复杂寻址、隐含寄存器更新和变长编码增加实现难度。

### 6.6 三类冒险

| 冒险 | 原因 | 例子 | 处理 |
| --- | --- | --- | --- |
| 结构冒险 | 同周期争用资源 | IF 与 load 争单端口内存 | 分离资源、加端口、停顿 |
| 数据冒险 | 所需结果尚未就绪 | 后指令读前指令结果 | 转发、停顿、调度 |
| 控制冒险 | 下个正确 PC 未确定 | 分支方向或目标未知 | 提前判断、预测、冲刷 |

分离指令/数据存储器或缓存可解决这里的典型冲突，不代表真实 CPU 没有其他结构冒险。

## 7. 流水线数据通路与控制

### 7.1 为什么需要级间寄存器

同一周期，各级处理不同指令，必须保存上周期产生的信息，避免被下一条覆盖。

![级间寄存器，PDF p.57](p057.png)

| 寄存器 | 典型内容 |
| --- | --- |
| IF/ID | 指令、该指令 PC |
| ID/EX | 源值、立即数、rs1/rs2/rd、PC、后续控制 |
| EX/MEM | ALU 结果、store 数据、rd、MEM/WB 控制 |
| MEM/WB | 内存数据、ALU 结果、rd、WB 控制 |

具体字段取决于分支判定阶段和优化方案。

### 7.2 结果、编号、控制必须跟随同一条指令

load 到 WB 才写回。如果直接取当时 ID 指令的 rd，就会写错寄存器：那已经是后续指令的编号。因此自己的 rd 必须一路从 ID/EX 传到 MEM/WB。

![load 的目的寄存器编号修正，PDF p.64](p064.png)

同理，store 携带自己的待存值，分支携带自己的 PC，控制位也随指令前进。

### 7.3 控制按阶段分组

- EX：ALUSrc、ALUOp。
- MEM：MemRead、MemWrite、相应实现中的分支控制。
- WB：RegWrite、MemtoReg。

ID 产生这些控制后，EX 用完自己的部分，继续传 MEM/WB；MEM 再传 WB。控制和数据必须同步保持、前进或作废。

![流水线控制，PDF p.73](p073.png)

### 7.4 两类流水图

多周期图横轴为周期、纵轴为指令，看重叠和停顿；单周期图固定一个周期，看每个部件当前服务哪条指令。

![多周期图，PDF p.69](p069.png)

从后级向前级的写回和转发路径值得重点关注：更老指令要给更年轻指令提供值，这是数据冒险控制的关键。

## 8. 数据冒险：转发与停顿

### 8.1 RAW 与程序依赖

```asm
add x19,x0,x1
sub x2,x19,x3
```

sub 要读 add 产生的新 x19，称 RAW（Read After Write，写后读）真相关。依赖是程序语义，是否停顿还取决于流水线时序与转发能力。

补充区分：

| 类型 | 含义 | 重命名能否消除 |
| --- | --- | --- |
| RAW | 后指令使用前指令产生的值 | 不能消除计算依赖 |
| WAR | 后指令写同名寄存器，前指令尚需读旧值 | 可以 |
| WAW | 两条指令写同名寄存器 | 可以 |

经典按序五级、固定读写阶段的模型主要处理 RAW；乱序多发射还需要管理 WAR/WAW。

### 8.2 旁路的核心思想

结果刚产生就送给消费者，无需等写回后再从寄存器读。

```text
EX/MEM.ALUResult → 当前 EX 的 ALU 输入
MEM/WB.WriteBack → 当前 EX 的 ALU 输入
```

![转发路径，PDF p.78](p078.png)

ALU 结果在 EX 结束时就绪，下一条下一周期才在 EX 使用，可由 EX/MEM 直接转发。更远的依赖可由 MEM/WB 转发。

### 8.3 转发选择编码

| ForwardA/B | 来源 | 含义 |
| --- | --- | --- |
| 00 | ID/EX | 原寄存器读取值 |
| 10 | EX/MEM | 较近的 ALU 结果 |
| 01 | MEM/WB | 较远的最终写回值 |

ForwardA 对应 rs1，ForwardB 对应 rs2。MEM/WB 的 load 转发必须提供加载值，不是地址。

### 8.4 转发条件

必须同时满足：生产者确实 RegWrite、rd 不是 x0、rd 匹配消费者所用源寄存器。

```text
EXmatchA = EX/MEM.RegWrite
           && EX/MEM.rd != 0
           && EX/MEM.rd == ID/EX.rs1(rs2)

WBmatchA = MEM/WB.RegWrite
           && MEM/WB.rd != 0
           && MEM/WB.rd == ID/EX.rs1(rs2)

若 EXmatchA：ForwardA=10
否则若 WBmatchA：ForwardA=01
否则：ForwardA=00
```

rs2 同理。**前提是该来源已具有所需数据**；EX/MEM 的 load 此时只有地址，不能把地址当加载值转发。经典 load-use 停顿负责避免错误使用。

### 8.5 双重冒险：最新值优先

```asm
add x1,x1,x2
add x1,x1,x3
add x1,x1,x4
```

第三条同时匹配两级的 x1，必须取第二条的新值：

$$Priority(EX/MEM)>Priority(MEM/WB)$$

所以 MEM/WB 生效条件是 `WBmatchA && !EXmatchA`，B 路对称。

p.81 的排除式把 `EX/MEM.rd = ID/EX.rs` 误写成了 `≠`。本笔记按“排除较新的匹配生产者”修正，不能照抄错误关系。

![包含转发单元的数据通路，PDF p.82](p082.png)

### 8.6 load-use 为什么仍停一拍

```asm
lw  x1,0(x2)
add x3,x1,x4
```

load 到 MEM 结束才得到数据，add 本来在同周期 EX 就需要值，不能把周期末结果送回周期开始。

```text
周期     1   2   3   4    5   6   7
lw       IF  ID  EX  MEM  WB
add          IF  ID  ID*  EX  MEM WB
EX 槽位             气泡
```

ID* 表示消费者保持在 ID，等下一周期由 MEM/WB 转发。

![load-use 气泡，PDF p.85](p085.png)

### 8.7 load-use 检测

- 检测的时刻：load 在 EX、消费者在 ID 时。
- 判定条件

```text
LoadUse = ID/EX.MemRead && ID/EX.rd != 0
          && ((uses_rs1 && ID/EX.rd == IF/ID.rs1)
              || (uses_rs2 && ID/EX.rd == IF/ID.rs2))
```

需判断源字段真的被读取，例如 I 型的 `[24:20]` 属于立即数，不能误判成有效 rs2。

### 8.8 如何停顿

| 动作 | 效果 |
| --- | --- |
| PCWrite=0 | PC 保持 |
| IF/IDWrite=0 | 消费者保持 ID |
| 进入 ID/EX 的控制清零 | EX 插入无副作用气泡 |
| 更老指令继续 | load 进入 MEM，产生数据 |

遇到lw指令且后续出现数据冒险时，仅依靠硬件就必须空出一个周期，而交给编译器改变指令执行顺序可以进一步优化。

### 9.3 优化策略

#### 9.3.1 缩短预测错误的代价（提前到EX/ID出结果）

提前到EX 出结果显然是没有问题的（把与门提前即可）；
提前到ID 阶段则要增加目标加法器、寄存器比较器（按位异或再按位或）、比较输入的转发和 IF/ID.Flush（用于将control置0，实现nop指令）。 好处是 taken 通常仅错取一条；代价是更早需要操作数，如果分支指令之前的ALU指令出现数据冒险，可能增加数据停顿。

![ID 判断与冲刷，PDF p.92](p092.png)
（图片里做了简化，实际上寄存器比较器会产生一个equal的信号，和branch进行与操作来判断是否跳转）

若分支在ID 出结果，则分支中的数据冒险具体情况如下：

| 生产者位置           | 额外等待      |
| --------------- | --------- |
| 中间至少隔一条的 ALU 指令 | 通常可转发，无停顿 |
| 紧邻前一条 ALU 指令    | 1 周期      |
| 中间隔一条的 load     | 1 周期      |
| 紧邻前一条 load      | 2 周期      |

#### 9.3.2 静态预测

总预测不跳转、总预测跳转；个人认为优化方法与9.3.1类似（可能两者本来就是一回事）。

#### 9.3.3 动态预测

对于更深的流水线或者多发射的情况，静态预测往往要为预测错误付出惨痛的代价。
于是我们讨论动态预测，我们只关注动态分支预测中的一种实现方法--分支预测缓存：用一块小的存储器保存下来上一次该指令执行时条件分支是否发生跳转，如果是，就从上次执行的地址中取出指令。

##### 9.3.3.1 1位预测器

仅记录上次 T/NT。循环行为多为 `T,T,…,NT`：最后一次退出错，改成 NT；下次进入第一轮又错。因此反复进入的内层循环常每轮两次误预测。初始状态与迭代数会影响具体结果。
而我们的理想状态是分支发生的频率和实际跳转率相匹配，于是我们引入多位预测器。

#### 9.3.3.2 2 位预测器

我们用2-bit 的饱和计数器来判断是否跳转：

| 状态 | 预测 | 实际 NT 后 | 实际 T 后 |
| --- | --- | --- | --- |
| 00 强不跳转 | NT | 00 | 01 |
| 01 弱不跳转 | NT | 00 | 10 |
| 10 弱跳转 | T | 01 | 11 |
| 11 强跳转 | T | 10 | 11 |

T 加 1、NT 减 1，到边界饱和，最高位决定预测。

![2 位预测器状态图，PDF p.98](p098.png)


![PHT 与状态更新，PDF p.99](p099.png)

整个过程分析：
PC 通过 Hash，将地址映射为k bit 的值（因为PHT只有2^k个入口），在PHT里面取对应的2-bit 的饱和计算值，用高位来判断是否跳转，FSM Update Logic再根据实际是否跳转更新。
#### 9.3.3.3 BTB

我们通过上面的过程可以提高预测的准确度，但是每次预测完后还需要ALU计算具体的跳转地址，那么我们的快速预测会失去一定优势。
我们通过BTB（Branch Target Buffer）缓存目标（即如果之前某个PC对应的是分支的地址，就把他记录下来），在 IF 按 PC 查询。若命中且预测 taken，可立即取目标；否则仍可能等目标计算。
这样可以在IF阶段就根据预测得到下一个指令的地址，相比ID阶段得到结果，又避免了一个延迟。

```text
BHT/方向预测器：跳吗？
BTB：跳到哪里？
```

![BTB 与其他预测方法，PDF p.101](p101.png)

## 10. 异常与中断

对应课件 p.104–116。

### 10.1 概念与流程

| 类型 | 来源 | 例子 |
| --- | --- | --- |
| 异常 exception | 与当前指令同步发生 | 非法指令、环境调用、访问异常、页故障 |
| 中断 interrupt | 外部或异步事件 | 定时器、外设请求 |

不同 ISA 术语可能不同。基本流程：保存相关 PC→记录原因→跳处理程序→软件修复/服务/报告→按规则恢复或终止。

- `sepc`：保存异常处理或恢复相关的指令地址。
- `scause`：保存中断/异常标识及原因。

课件入口 `0x000000001C090000` 仅是例子，不是 RISC-V 固定地址；实际取决于特权级及配置。

### 10.2 直接与向量入口

统一入口先读取原因再分派；向量入口按原因选择对应入口或跳转。p.106 的“基址+原因偏移”是概念示意，不能泛化为所有 RISC-V 异常与模式的精确地址规则。

### 10.3 流水线精确异常

若 add 在 EX 检测到故障：

1. 更老指令完成。
2. 故障 add 不写错误结果。
3. 更年轻指令冲刷，禁止副作用。
4. 写 sepc、scause，进入处理程序。

![异常处理数据通路，PDF p.109](p109.png)

精确异常要求软件观察到的状态像在某个指令边界暂停：**故障之前已完成，故障及之后未留下不该保留的可见效果。**

可重启异常在修复后重取故障指令；不是所有异常都原地重试，例如环境调用通常按约定返回后续指令。

### 10.4 多异常与非精确异常

同周期多个在途指令异常，优先处理**程序顺序最老指令**，冲刷年轻指令；不是看哪个电路先报告。

非精确异常保存当时流水状态，让软件判断哪些应完成或撤销，硬件可能简单，但软件恢复复杂。复杂乱序多发射尤其需要精确异常支持。

### 10.5 原因码的课件矛盾

p.105 写“12=hardware malfunction”，但 p.116 原因表列：

| Interrupt | code | p.116 的含义 |
| --- | --- | --- |
| 0 | 2 | Illegal instruction |
| 0 | 3 | Breakpoint |
| 0 | 8 / 9 | U-mode / S-mode 环境调用 |
| 0 | 12 | **Instruction page fault** |
| 0 | 13 | Load page fault |
| 0 | 15 | Store/AMO page fault |
| 1 | 1 / 5 / 9 | Supervisor software / timer / external interrupt |

不要背“12=硬件故障”。该表的保留项也有版本背景，不是所有版本完整规范。

![课件 scause 表，PDF p.116](p116.png)

add 故障是恢复机制的教学例子，不代表 RISC-V 普通 add 的整数溢出必然产生异常。

## 11. 指令级并行与静态多发射

对应课件 p.117–129。

### 11.1 ILP 与 IPC

ILP（Instruction-Level Parallelism）是可被重叠/并行执行的指令所提供的并行性。可通过加深流水线、增加每周期发射数量来利用。

$$IPC=\frac{\text{完成指令数}}{\text{周期数}},\qquad CPI=1/IPC$$

倒数关系要求统计口径一致。4 GHz、4 发射峰值为 16 G instructions/s（16 BIPS），IPC=4、CPI=0.25；实际会受依赖与资源限制。

### 11.2 静态与动态

| 类型 | 决策者 | 特点 |
| --- | --- | --- |
| 静态多发射 | 编译器 | 组成发射包、检查依赖、必要时填 nop |
| 动态多发射 | CPU | 运行时选取就绪指令、解决冒险 |

静态发射包类似 VLIW（Very Long Instruction Word），一次编码多个并行操作。包内允许何种依赖由 ISA/硬件契约决定。

### 11.3 推测的共同思想

先猜测尚未确定的条件并提前工作，正确则保留，错误则回滚。可推测分支方向、提前 load。

编译器推测通过重排与修复代码实现，可能需要 ISA 支持延迟异常；硬件推测把结果和异常暂存到确认需要时。无效路径的 load 不能提前向程序报告不应出现的异常。

### 11.4 课件静态双发射模型

每个 64 位、8 字节对齐发射包有两个槽：ALU/branch 在前，load/store 在后，空槽 nop。这是教学模型，不是标准 RISC-V 的统一打包规则。

同包 ALU 结果不能立即供同包访存计算地址；load-use 一周期等待依然存在，现在可能同时浪费两个槽，编译调度更重要。

### 11.5 调度例题

```asm
Loop:
    ld   x31,0(x20)
    add  x31,x31,x21
    sd   x31,0(x20)
    addi x20,x20,-8
    blt  x22,x20,Loop
```

课件安排：

| 周期 | ALU/branch | Load/store |
| --- | --- | --- |
| 1 | nop | `ld x31,0(x20)` |
| 2 | `addi x20,x20,-8` | nop |
| 3 | `add x31,x31,x21` | nop |
| 4 | `blt x22,x20,Loop` | `sd x31,8(x20)` |

指针提前减 8，store 偏移必须改 +8，保持原地址。

$$IPC=5/4=1.25$$

这是稳态有用指令口径，不计填充 nop 为有效工作，也未计起止和额外分支损失。

![静态双发射调度，PDF p.127](p127.png)

### 11.6 循环展开

复制若干迭代暴露独立工作，减少每元素的控制开销；使用 x28、x29、x30、x31 等不同寄存器，避免重复名字产生反相关。

四次展开后，12 条 load/add/store 加指针更新、分支共 14 条有用指令，8 周期：

$$IPC=14/8=1.75$$

![循环展开与调度，PDF p.129](p129.png)

首包 `addi x20,x20,-32` 与 `ld x28,0(x20)` 并发，load 使用包内读取的旧基址；后续在新基址上用 24、16、8 等偏移。必须遵守本模型读操作数和包内依赖规则。

代价：代码和寄存器需求增长，真实循环还要处理尾部。重命名仅消除名字依赖，不消除真相关。

## 12. 动态调度、重命名与推测

对应课件 p.130–137。

### 12.1 超标量与乱序

动态多发射称超标量 superscalar，CPU 运行时选择发射 0、1、2…条。乱序执行使无关的后续操作绕过等待者：

```asm
ld   x31,20(x21)
add  x1,x31,x2       # 等 load
sub  x23,x23,x3      # 可以先做
andi x5,x23,20       # 等 sub，与 load 无直接依赖
```

不能违反 RAW：add 仍等 x31，andi 仍等新 x23。

### 12.2 动态 CPU 结构

![动态调度 CPU，PDF p.132](p132.png)

| 部件 | 作用 |
| --- | --- |
| 取指/译码/派发 | 识别指令、分配资源 |
| 保留站 | 保存操作、已到达值和未到达值的生产者标签 |
| 功能单元 | 并行执行整数、浮点、访存 |
| 结果网络 | 把结果送到等待者 |
| ROB 重排序缓冲 | 按程序顺序记录在途指令，保存结果和完成状态 |
| 提交单元 | 让正确且最老的已完成指令更新体系结构状态 |

**执行可以乱序，提交保持顺序。执行完成不等于已经提交。**

### 12.3 动态寄存器重命名

体系结构寄存器名可映射到不同内部版本。源值已就绪则复制/关联其值，未就绪则记生产者标签；新的同名写入分配新版本，避免覆盖旧消费者仍需的值。

课件保留站与 ROB 有效提供重命名，消除 WAR/WAW；RAW 真相关仍需等待生产者。

### 12.4 推测与按序提交

```text
预测 → 派发/重命名 → 就绪后执行 → 暂存结果
                                 ↓
                   确认正确且轮到最老 → 提交
                   误预测或异常      → 丢弃年轻操作并恢复
```

推测 load 可尝试越过先前 store，但须验证地址冲突；错误需恢复。课件还列有效地址预测、值预测、store→load 旁路等思路，不表示每颗 CPU 都采用全部方法。

异常也暂存，只有正确路径上轮到该指令提交时再按序报告，维护精确异常。

### 12.5 为何还需要运行时调度

编译器不知道某次 cache miss、分支实际结果，也难适配同 ISA 不同微架构的全部延迟；动态硬件可以利用运行时信息。

局限：真相关、指针别名、有限窗口、内存延迟和带宽都会限制 ILP，不能指望发射宽度翻倍就性能翻倍。

### 12.6 功耗限制

更深、更宽、复杂预测、保留站和重命名网络消耗面积与功率。p.137 的历史案例说明单核复杂度和频率不能无限增长，多个简单核心有时更节能。多核并行与单核 ILP 是不同层次。

```text
→ ROB/保留站 → 多单元乱序执行 → 按序退休
```

课件图列多个译码器、微操作缓冲、128 项 ROB、36 项保留站及多级缓存。这些是该代实现细节，核心是理解各模块职责。

性能图展示 CPI 和分支相关统计，说明流水停顿、推测与访存损失使实际表现偏离理想峰值。

### 13.4 矩阵乘法：SIMD 与展开

p.143–144 的 `dgemm` 使用 AVX，按图示列主序数组计算：

$$C_{ij}\mathrel{+}=\sum_k A_{ik}B_{kj}$$

- `__m256d` 放 4 个 double（256/64=4）。
- `_mm256_load_pd` 加载 4 个连续元素。
- `_mm256_broadcast_sd` 把一个 B 元素复制到 4 个位置。
- 向量乘、加一次处理 4 个元素，利用 SIMD。
- `UNROLL=4` 使用 4 个独立向量累加器，一组覆盖 16 个元素，暴露多条可交错执行的计算链。
- 部分和保留寄存器，完成 k 循环再写 C，减少反复读写。

SIMD 是一条指令处理多个数据；ILP 是多条指令重叠执行。AVX 和展开分别促进这两种并行，可叠加使用。

汇编对应：`vmovapd` 搬运、`vbroadcastsd` 广播、`vmulpd/vaddpd` 乘加、`cmp/jne` 控制循环。以指令为准，个别行的寄存器注释不必照背。

## 14. 易错点与课件纠错

### 14.1 核心误区

| 误解 | 正确理解 |
| --- | --- |
| 流水线降低每条指令延迟 | 主要改善吞吐，延迟可能增加 |
| 五级必然五倍 | 有不均衡、开销、起止和冒险 |
| 转发解决一切相关 | 未产生的数据不能转发 |
| 有相关就要停顿 | 可被转发/调度隐藏 |
| Branch=1 就跳 | beq 还看 Zero |
| x0 需要转发新值 | x0 恒为 0，应排除 |
| 停顿就是全线冻结 | 保持年轻指令，让老生产者继续 |
| 冲刷与停顿一样 | 冲刷作废；停顿保留以后继续 |
| 多发射一定乱序 | 可按序多发射 |
| 重命名消除所有依赖 | 仅消除名字相关 |
| 方向正确就无分支损失 | 还要及时有目标地址 |
| 宽度翻倍性能翻倍 | 受真相关、窗口、资源和内存限制 |

### 14.2 课件需警惕的位置

| PDF 页码 | 问题/限制 | 正确处理 |
| --- | --- | --- |
| p.36 | jal 缺完整路径说明 | 实际扩展后重新计时 |
| p.44 | 定长讨论是基础子集 | 不泛化为所有扩展 |
| p.81 | EX 排除式寄存器比较写反 | 应排除 `rd=rs` 的更新生产者 |

| p.90 | 位移采用半字单位 | 区分已补零字节偏移，避免重复移位 |
| p.98 | “两次错误”概括过度 | 弱状态一次错误可改方向 |

### 14.3 课件末尾的设计提醒（p.146–148）

流水线思想简单，细节难在冒险、恢复和精确控制；实现受工艺、晶体管、连线与功耗影响。ISA 与数据通路相互塑造，复杂寻址、隐含更新会增加负担。延迟分支把某种时序暴露给软件，在更深流水线中可能成为包袱。ILP 受程序相关限制，复杂硬件又受功耗墙限制。

## 15. 做题方法与复习自查

### 15.1 单周期题

1. 写指令语义：读谁、算什么、写哪里、下个 PC。
2. 标使用部件，确定 MUX 选择。
3. 决定写寄存器、读写内存等控制。
4. opcode→ALUOp→具体运算。
5. 沿串行依赖求最长路径；并行部件不能全部串行相加。

### 15.2 流水线题

1. 画理想五级对角线。
2. 标 rs1/rs2/rd 与实际使用阶段。
3. 标生产者何时产生值。
4. 检查题设转发路径是否及时供给。
5. 不满足则插泡并冻结前级。
6. 加入分支判断、预测与冲刷。
7. 数时间线，用 `n+4+S` 核对。

补充练习：

```asm
lw  x5,0(x1)
add x6,x5,x2
sub x7,x6,x3
```

经典五级、完整 ALU 转发、无其他冒险：load→add 停 1，add→sub 转发，总 `3+4+1=8` 周期。无转发时还要确认同周期先写后读约定，不能套固定数字。

### 15.3 预测器题

列“更新前状态→预测→实际→对错→更新后状态”。先预测后更新；共用表项的分支按真实执行顺序更新同一状态。

### 15.4 多发射题

先画依赖，再看槽类型和资源，用独立工作填等待；移动指针更新后重新计算偏移。IPC 区分有效指令与填充 nop、稳态与起止周期。

### 15.5 公式速查

| 用途 | 规则 |
| --- | --- |
| CPU 时间 | $IC\times CPI\times T_{clk}$ |
| 单周期周期 | 最慢指令关键路径 |
| 流水周期 | 最慢级+级间开销 |
| k 级 n 条理想单发射 | $n+k-1$ 周期 |
| 含额外损失 | $n+k-1+S$ 周期 |
| 长程序 CPI | $1+\text{平均额外停顿}$ |
| 分支损失 | $f_{branch}r_{mispredict}P_{mispredict}$ |
| IPC | 完成指令数/周期数 |
| 加速比 | 原时间/新时间 |
| beq 条件 | $Branch\land Zero$ |
| 转发优先 | EX/MEM 比 MEM/WB 更新 |

## 16. 原有笔记的保留与扩展

原笔记的问题是：**“ALUOp 与 ALU 控制线产生的四位数据有什么区别？”**原理解正确：主控制器按 opcode 初步判断指令大类，ALU control 再结合 funct3、funct7 产生具体运算信号，从而划分译码职责。
